# GitHub-based shared trip workspace

## Goal

Migrate camping-trip planning from Google Drive/Sheets to a GitHub repo so that
the user (alex-nedelkoff) and a collaborator (pizza-zip) — both heavy Claude
Code users — can edit, push, and preview trip docs in markdown and HTML.

The existing Python tooling (`ontario_parks.py`, `trip_planner.py`,
`weather.py`, `route_map.py`) and data files come along. Future trip pages are
generated from markdown sources rather than from a Google Sheet.

## Non-goals

- Replacing the Ontario Parks availability tooling (kept as-is).
- Building a full PR review workflow with branch protection (overkill for two
  people).
- GitHub Pages or per-PR preview deploys (private repo; out of scope).
- Two-way sync between markdown and any external system.

## Constraints

- Repo is **private**. Site numbers + exact dates on a public repo are
  identifying for backcountry trips, so we accept the small HTML-preview
  friction in exchange for not publishing trip locations.
- htmlpreview.github.io cannot reach private repos. HTML preview is local-only:
  clone + `python3 -m http.server` → open in a browser.
- GitHub renders markdown natively when browsing the repo on github.com after
  login, so day-to-day collaboration needs no extra tooling.
- The collaborator may not have the existing Python toolchain set up. Markdown
  edits must work without running any local scripts; only the HTML rebuild
  step needs Python.

## Components

### Repo init & collaborator

- `git init` in `/Users/alex/Documents/camping-planner`.
- Initial commit migrates everything as listed above (with the `legacy/` move
  done as part of the first commit so history starts clean).
- `gh repo create alex-nedelkoff/camping-planner --private --source=. --push`.
- Invite: `gh api -X PUT repos/alex-nedelkoff/camping-planner/collaborators/pizza-zip -f permission=push`.

### `.gitignore`

```
__pycache__/
*.pyc
.venv/
.DS_Store
private/
*.local.md
```

`private/` and `*.local.md` are escape hatches: anything genuinely sensitive
(emergency contact phone numbers, satellite-messenger PINs, etc.) goes there
and stays local. Both collaborators sync these out-of-band.

### `build_trip.py` (new)

Replaces the Sheet-driven half of `trip_planner.py`. Markdown is the source
of truth.

**CLI:**

```
python3 build_trip.py trips/killarney-2026-05/
```

**Inputs (from the trip directory):**

- `trip.md` — YAML frontmatter (single source of structured data) plus a free
  intro section. Frontmatter fields:
  - `park` (slug, must match `parks.json`)
  - `start_date`, `end_date` (ISO dates)
  - `participants` (list of names)
  - `meeting_point` (string, optional)
  - `access_point` (string, optional — e.g., "George Lake")
  - `nights` (list of `{date, site, location}` for backcountry trips)
- `itinerary.md`, `gear.md`, `food.md`, `packing.md`, `costs.md` — rendered as
  labelled sections in the order: Intro → Itinerary → Route map → Weather →
  Gear → Food → Packing → Costs.
- `route.gpx` or `route.kml` (optional) — passed to existing `route_map.py`
  for the Leaflet+SVG dual map. If both exist, `.gpx` wins. If neither
  exists, the Route map section is omitted from the rendered HTML.

**Inputs (from repo root):**

- `parks.json` — drive time from Ajax, GPS, mapId.
- `park_activities.json` — curated tips, surfaced in the intro.
- `weather.py` — historical-or-forecast widget, auto-switches at 16-day
  cutoff. The May 15 trip is well within forecast range.

**Output:**

- `trip.html` written to the same trip directory. Self-contained: inline CSS
  and JS, Leaflet from CDN with SVG fallback for offline. Same look-and-feel
  as the legacy `trip_killarney_jul10.html`.

**Markdown handling:**

- `markdown` Python package added to `requirements.txt`. Stdlib has no
  markdown parser.
- Task lists (`- [ ]`) preserved as real `<input type="checkbox">` elements
  with localStorage persistence (matches legacy behavior).

**Scope cuts vs `trip_planner.py`:**

- No `gws` calls, no Sheet creation, no Drive upload.
- No participant-tab parsing — participants come from `trip.md` frontmatter.

### Templates

`templates/trip-template/` is a directory you copy:

```
cp -r templates/trip-template trips/<new-trip-name>/
```

Each template file has placeholder content showing the expected structure
(packing categories, an example itinerary day, etc.) — enough to remove
ambiguity, not so much that you fight it.

### README rewrite

Tailored for pizza-zip's first day on the repo:

1. **Quick start:** clone, `cd trips/killarney-2026-05/`, edit any `.md` in
   your editor, `git add … && git commit -m "…" && git push`. Pull rebase
   before you start.
2. **Markdown preview:** click any `.md` file on github.com — it renders.
3. **HTML preview:** `python3 -m http.server` from repo root, browse to
   `http://localhost:8000/trips/<trip>/trip.html`.
4. **Start a new trip:** `cp -r templates/trip-template trips/<name>/`,
   fill in `trip.md`, run `python3 build_trip.py trips/<name>/`.
5. **Sensitive content:** anything that shouldn't be in git lives in
   `private/` (gitignored).

## Workflow

- Both push directly to `main`. No PR overhead.
- Convention: pull with rebase before starting work; commit messages in
  imperative ("update packing for canoe trip"); regenerate `trip.html` and
  commit it together with markdown changes.
- For the rare case where one of you wants the other to review before merge,
  open a PR — but it's not the default.

## First trip: Killarney 2026-05-15 → 2026-05-18

Backcountry canoe trip, 3 nights:

| Date            | Site | Lake          |
|-----------------|------|---------------|
| Fri 2026-05-15  | 61   | OSA Lake      |
| Sat 2026-05-16  | 82   | Baie Fine     |
| Sun 2026-05-17  | 12   | Killarney Lake|

Return Mon 2026-05-18. Trip is 6 days out at spec-write time, so weather
widget pulls live forecast (not historical climate).

`trip.md` frontmatter captures the daily site assignments under `nights:`
so `build_trip.py` can render the per-night table. The site-assignment
data is the load-bearing reason this repo is private rather than public.

No availability check needed — sites are already booked.

## Implementation order

Each step is independently recoverable; the repo is usable to pizza-zip
after step 3, even before `build_trip.py` exists.

1. Local repo init: `.gitignore`, move legacy files, copy in templates and
   the empty Killarney trip skeleton, README rewrite, initial commit.
2. `gh repo create … --private --source=. --push`.
3. Invite pizza-zip via `gh api`.
4. Implement `build_trip.py` + add `markdown` to `requirements.txt`. Verify
   it renders the legacy-page sections (intro, itinerary, weather, route,
   gear, food, packing with checkboxes, costs).
5. Fill in Killarney trip markdown (frontmatter with the three nights,
   itinerary draft, baseline gear/food/packing for a backcountry canoe
   trip).
6. Run `build_trip.py` to render `trip.html`. Commit both md and html.
7. Smoke-test HTML locally via `python3 -m http.server`. Confirm checkboxes,
   weather widget, and route map (if present) all work.

## Risks & open questions

- **Backcountry-specific template flavor.** The starter template is
  generic; the Killarney trip's filled-in content will be canoe-specific
  (PFDs, dry bags, water filter, bear-hang, no cooler). If we plan more
  car-camping trips later, we may want a `trip-template-canoe/` and a
  `trip-template-car/` rather than one generic.
- **Route file.** No GPX yet for the Killarney loop. The HTML page will
  render without a map; if a route file is added later, just drop it in
  the trip folder and re-run `build_trip.py`.
- **Markdown package version.** `requirements.txt` should pin a specific
  version of `markdown` to avoid renderer drift between collaborators.
- **`trip_planner.py` retirement.** Kept under `legacy/` for now. Once
  `build_trip.py` covers the cases we care about, it can be deleted in a
  follow-up.
