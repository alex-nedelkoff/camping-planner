# Campsite Search — Design

**Date:** 2026-05-25
**Branch:** `local/water-polygon-union`
**Status:** Approved (design), pending implementation plan

## Problem

We've pulled detailed site data for Balsam Lake (532 sites: attributes, photos,
campground, equipment type) and baked it into a one-off standalone HTML preview
(`legacy/balsam_lake_preview.html`) generated by `compile_balsam_v2.py` in the
job dir. We want this as a first-class, browse-only tab in the app, reachable
from the home page, and structured so that **future parks can be added without
code changes** — just by pulling their data and dropping in a file.

## Scope decisions (from brainstorming)

- **Static site browser only.** Show attributes, photos, campground, equipment
  type. **No availability** — availability is date-specific and rate-limited;
  the existing home-page `/api/availability` check stays the place for that.
- **Pure reference / browse-only.** No links into trip planning, no schema
  changes to `trip.json`. (A site number can be noted manually.)
- **Data-driven, multi-park.** One normalized survey file per park; the index
  page and filters are derived from whatever survey files exist.

## Architecture

### Data layer

Promote the job-dir `compile_balsam_v2.py` into a reusable, committed script:

`scripts/compile_site_survey.py`

Inputs:
- Raw Camis resources JSON for the park (e.g. `balsam_resources.json`).
- The repo's attribute catalog `api_attribute_filterable.json`.
- CLI args: `--resources <path> --park-slug <slug> --park-name "<name>" --out <path>`.

Output — a **normalized survey JSON** at `app/data/site_surveys/<park-slug>.json`:

```jsonc
{
  "park_slug": "balsam-lake",
  "park_name": "Balsam Lake Provincial Park",
  "pulled_on": "2026-05-24",
  "site_count": 532,
  "sites": [
    {
      "name": "312",
      "campground": "Sites #300-360 (...)",
      "equipment_bucket": "Trailer / motorhome",
      "description": "...",
      "max_capacity": 6,
      "attributes": { "Privacy": "Good", "Site Length (m)": 17, "Site Shade": "Partial - PM" },
      "photos": ["https://.../1.jpg", "https://.../2.jpg"]
    }
  ]
}
```

Carried over from the proven compile logic:
- The enum-parsing fix (Camis stores enum values in `definedAttributes[].values`
  list; catalog enum labels under attribute `values`, not `enumValues`).
- `equipment_bucket` derivation (Tent only / Small trailer-pop-up / Trailer-motorhome
  / RV-big-rig / Other-special) from allowed-equipment count + site length.
- `campground` label derivation from site-number ranges / name prefixes.
- Photo URL extraction from `photos[].photoUrlResult.url`.

Availability code is **removed** from the ported script (no `avail/` reads, no
`availability` column).

### Discovery / service layer

`app/services/site_surveys.py`:
- `list_surveys() -> list[dict]` — scan `app/data/site_surveys/*.json`, return
  lightweight summaries `{park_slug, park_name, site_count, pulled_on}` for the
  index page. Sorted by park name.
- `load_survey(slug) -> dict | None` — load and return one full survey, or None
  if the file is missing.

Survey directory path added to `app/config.py`:
`SITE_SURVEYS_DIR = APP_DIR / "data" / "site_surveys"`.

### Routes — `app/routes/sites.py`

- `GET /sites` -> `sites_index.html`. Lists available surveys as cards. If none
  exist, an empty-state message.
- `GET /sites/{slug}` -> `sites_park.html`. Loads the survey; 404 if missing.
  Passes the site list plus derived filter option sets to the template.

Registered in `app/main.py` alongside the other routers.

### Filter option derivation (server-side, per park)

From the loaded survey's sites, compute:
- **Campgrounds** — sorted distinct `campground` values.
- **Privacy** — fixed order `[Good, Average, Poor]` + `Unrated` (blank), only
  shown if present in data.
- **Equipment type** — fixed bucket order, intersected with buckets present.
- **Site length (m)** — numeric min/max bounds across sites that have the value.

These are passed to the template so the markup only renders filters relevant to
that park's data.

### Templates + JS (cartographer aesthetic, in-app)

- `app/templates/sites_index.html` — extends `base.html`; park survey cards;
  `nav_band` with `home_href`.
- `app/templates/sites_park.html` — extends `base.html`; the filter bar + site
  grid + photo lightbox. Reuses site CSS tokens (`--ink`, `--rust`,
  `--parchment`, `--rule`, fonts) instead of the standalone file's inline styles.
- `app/static/js/site_search.js` — ports the preview's client filter logic:
  checkbox groups (campground/privacy/equipment), numeric length range,
  search-box text match, has-photos toggle, reset / all / none, live count,
  and the image lightbox. Operates on `data-*` attributes on each `.site` card.
- `app/static/css/` — add a new `sites.css` stylesheet for the
  grid/card/filter styling, mirroring the preview's look within the app theme.

### Navigation

- Home page header (`index.html`): add a **"Campsite Search"** button/link to
  `/sites`, beside the existing "Map overlay" / "New Trip" actions.
- `/sites` and `/sites/{slug}` include the existing `nav_band` partial for a
  consistent back-to-home affordance.

## Migration

Run `scripts/compile_site_survey.py` once against the job-dir
`balsam_resources.json` to produce `app/data/site_surveys/balsam-lake.json`,
committed with the code. The raw 1.7 MB resources JSON stays in the job dir /
`legacy` and is **not** committed. Photos remain hotlinked from the Camis CDN.

## Testing

- **Service unit tests** (`tests/test_site_surveys.py`): `list_surveys()` returns
  summaries from fixture files; `load_survey()` returns full data; missing slug
  returns None. Use a temp/fixture survey dir.
- **Route smoke tests** (`tests/test_sites_routes.py`): `/sites` renders 200 and
  lists the park; `/sites/balsam-lake` renders 200 with site cards and filter
  controls; `/sites/does-not-exist` returns 404.
- **Compile script test**: feed a tiny synthetic resources blob + catalog,
  assert the normalized output shape (attributes mapped, enum labels resolved,
  equipment bucket assigned, photos extracted).
- **Playwright**: load `/sites/balsam-lake`, toggle a Privacy checkbox, narrow
  the length range, confirm the visible count updates and a lightbox opens.

## Out of scope (YAGNI)

- Availability display or live API calls from this page.
- Linking sites to trips / `trip.json` changes.
- Editing survey data through the UI (surveys are generated artifacts).
- Cross-park unified search (one park per page is enough for now).

## Future-park workflow (documented in the script docstring)

1. Pull the park's Camis resources JSON (reuse the existing pull approach).
2. `python scripts/compile_site_survey.py --resources <raw.json>
   --park-slug <slug> --park-name "<Name>" --out app/data/site_surveys/<slug>.json`
3. Commit the new survey file. It appears on `/sites` automatically; filters
   adapt to its data.
